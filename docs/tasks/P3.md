## Steps

### 1. Start the downloads now (they run in the background)

Put files under `data/raw/` (git-ignored). Tell P1 the exact paths once they land.

| Folder | What | Where |
|---|---|---|
| `data/raw/lola/` | LOLA south pole DEM, **20 m/px, 80–90°S** (GeoTIFF; several GB) | NASA PGDA: https://pgda.gsfc.nasa.gov/products/90 |
| `data/raw/lola_illum/` | LOLA polar illumination maps (south, average illumination) | PDS LOLA node: https://imbrium.mit.edu/BROWSE/EXTRAS/ILLUMINATION and https://pgda.gsfc.nasa.gov/products/69 |
| `data/raw/diviner/` | Diviner **Polar Resource Product** (south; annual mean and max temperature) | PDS Geosciences Node / ODE: https://pds-geosciences.wustl.edu/missions/lro/diviner.htm |

- Also register on ISRO PRADAN (https://pradan.issdc.gov.in). Approval can take a while, so start now even though Chandrayaan-2 layers are a stretch goal.
- If a file turns out larger than you can download in time, tell P1 straight away rather than waiting.
- Add each dataset to `ACKNOWLEDGEMENTS.md` with its citation. For example, illumination maps: Mazarico et al. 2011, *Icarus* 211.

### 2. Make the app read `results/` (P2's committed outputs)

P2 commits these files. All scores are **0–1**; multiply by 100 for display.

| File | Use it for |
|---|---|
| `results/predictions.parquet` (`cell_id, landing_score, resource_score, landing_uncertainty, resource_uncertainty, confidence, features_version`) | Join on `cell_id`. Show **model uncertainty** on the site card next to confidence. |
| `results/pairs.parquet` (`landing_cell_id, ice_cell_id, distance_km, route_cost, landing_score, resource_score, confidence, combined_score`) | Replace the SYNTHETIC placeholder pairs. Draw a line from landing to ice cell on the map for the selected pair, if time allows. |
| `results/validation.csv` | Plot Shackleton rim and Malapert massif as labelled markers on the heatmap. Show "rank N, in top-K: yes/no". |
| `results/metrics.json` | A small "About the model" expander: R² for MLP vs baseline, plus `features_version` |

Rules for this step:
- **Always keep the fallback.** If `results/` is missing, the app must still run on synthetic data, with the banner.
- **Read `features_version` and show it.** If it starts with `v0`, the banner must say SYNTHETIC, even if the files are present.
- Keep the live weight sliders. They re-rank with the transparent scoring formula. The model predictions are a separate, labelled view.

### 3. Swap in P1's scoring (when P1 says `scoring.py` is on main)

In `app/main.py`, `normalised()`, `weighted_score()` and `passes_constraints()` duplicate what P1 is writing (see the **SWAP POINT** comment). Replace them with calls to P1's API:

```python
from src.scoring import normalise, weighted   # P1
```

Keep your caching. `normalise` doesn't depend on the weights, so cache it and only rerun `weighted` when the sliders move.

**Done when:** the app's top-10 matches `src.scoring.score()` for the default weights, and `make test` passes.
